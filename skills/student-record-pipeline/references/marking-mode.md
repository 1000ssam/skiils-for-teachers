## 왜 이렇게 하나

AI가 학생 원문 전체를 읽고 **무엇이 의미 있는지까지 고르면**, 그 안목은 교사 렌즈 고유라 자동화가 어렵고
잘못 고르면 **검수 비용이 작성 비용을 넘는다.** 마킹은 그 선택을 교사에게 되돌린다 —
교사가 원문에 근거를 표시하고, AI는 표시된 것만으로 렌더한다.

**ledger(D1)와의 관계:** ledger는 쓴 **뒤** 근거를 대조하는 사후 장치, 마킹은 쓰기 **전** 재료를 제한하는 사전 장치다.
둘은 배타적이지 않다 — 병용하면 ledger의 `span`이 마킹 집합에 속하는지를 결정론으로 검사할 수 있다(부분문자열 대조).

## 하드바인딩 (불변식)

**사실 원천 = 표시된 span + 그 '왜' + 역량 + 활동맥락. 이게 전부다.**

- 표시되지 않은 원문은 **렌더 입력에 넣지 않는다.** 지시로 막는 게 아니라 구조로 막는다
  (원문을 넣고 "보지 마라"고 쓰면 반드시 샌다).
- 마킹이 얇으면 세특도 짧다(헌법 4). **분량을 채우려 재료를 부풀리면 헌법 2 위반.**
- 표시 안 된 사실(다른 사건·인물·날짜)을 배경지식으로 끌어오지 않는다.

## 위임 — 마킹이 0개인 학생

교사 입력은 **재료·수준 두 축 모두 부분 지정**이 가능하다. 안 정한 칸만 AI가 메운다.

| 교사가 준 것 | AI가 하는 것 |
|---|---|
| 하이라이트 **있음** | 표시된 것만으로 렌더 — 원문은 입력에 안 들어간다(하드바인딩) |
| 하이라이트 **0개** | 원문을 읽고 무엇이 의미 있는지 **직접 고른다**(위임) |
| `level` 지정 | 그 도달 진술 허가 범위 안에서(아래 §level) |
| `level` 미지정 | 재료 두께로 추정 |

- 🚨 **부분 마킹은 위임이 아니다.** 하이라이트가 **하나라도** 있으면 하드바인딩이고 원문은 안 들어간다.
  **0개일 때만** 위임한다. 안 그러면 "칠한 것 + 원문"이 섞여 하드바인딩이 조용히 새는 최악이 된다.
  구현은 **개수로 갈라라** — "마킹이 부실해 보이면 원문도 준다" 류의 판단을 코드에 넣지 않는다.
- 🚩 **위임은 편의가 아니라 비용이다.** 폐기한 모드 A의 동작이 그대로 돌아오는 것이므로,
  검수 비용이 작성 비용을 넘는 구간으로 되돌아간다. 검수에서 위임 학생을 **눈에 띄게 표시**하고,
  반복해서 물리면 답은 다시 쓰는 게 아니라 **그 학생을 마킹하는 것**이다.
- 위임 학생에게도 나머지는 전부 같다 — 구조·문체·바이트·금지·검수 루프·`level` 규칙.

## 마킹 스키마 (교사 입력 — 학생 1명 = 레코드 1개)

```jsonc
{
  "id": "<식별키>", "name": "<이름>",
  "highlights": [
    { "section": "<섹션 키>",        // 스펙의 sections 정의를 따름
      "text": "<원문 글자 그대로>",   // 🚨 OCR 오탈자 보존 — 고치면 대조가 깨진다(D1과 동일 규율)
      "why":  "<왜 이 부분이 의미 있나>" }
  ],
  "competency": "<이 학생에게서 관측된 것 — 무엇에 도달했나>",
  "level": "상|중|하|\"\"",           // 얼마나 — 스펙 rubric 척도를 그대로 씀
  "extra": "<기타 요구사항 — 분량·톤·강조점, 또는 교사가 관찰한 사실>",

  "done": false,                     // 초안 요청 — 렌더 트리거(세특이 나오기 *전*의 행동)
  "approved": false,                 // 확정 — 이관 게이트(나온 *후*의 판정)
  "approved_at": null,
  "held": false, "held_at": null,    // 판정 보류 — "못 정하겠다, 나중에"(재렌더 안 함)
  "rejects": [{ "at": "<ISO>",
                "reason": "<왜 물렸나 — 다음 렌더 입력이 된다>",
                "setuk":  "<물린 그 본문 — 스냅샷>" }],
  "material_at": "<ISO>"             // 재료가 마지막으로 바뀐 시각 — 대기열 판정 기준
}
```

- `why`는 비어 있어도 된다. 다만 **빈 span은 사실 재료로만 쓰이고 도달 진술의 근거로는 못 쓴다.**
- `competency`(무엇에)와 `level`(얼마나)은 **역할이 다르다.** 한 칸에 섞지 않는다.
- 원문 전체는 교사 화면에만 있고 렌더 입력에는 들어가지 않는다(하드바인딩). **예외는 위임뿐**(§위임).
- 🚨 **`done`과 `approved`를 같은 모양의 컨트롤로 두지 않는다.** 시점이 다르다 —
  `done`은 세특이 나오기 전, `approved`는 나온 뒤. UI에서 **체크박스=요청 / 버튼=판정**으로 성격을 가른다.
- 🚨 **`approved`를 없애는 안은 기각.** 없애면 "안 읽음"과 "읽고 괜찮음"이 구분되지 않는다.
  생기부는 법적 문서이고 최종 책임이 교사에게 있으므로(헌법 6) 이관 앞에 게이트가 필요하다.
- `rejects`는 **누적**한다(지우지 않는다). 딱지를 지울 필요가 없는 이유는 아래 대기열 규칙 참조.
- 🚨 **`rejects[i].setuk`(물린 본문 스냅샷)을 반드시 남긴다.** 사유만 남기면, 다음 렌더가 초안 파일을
  덮어쓰는 순간 교사가 *"이상하다고 느낀 그 문장"* 이 어디에도 없다. 2회 이상 물리면 더 심하다 —
  디스크에서 읽는 방식은 직전 것 하나만 남는다. 스냅샷은 **반려 이력을 자기완결로** 만든다.
  렌더 프롬프트에도 회차별로 싣는다("이 버전들이 전부 물렸다"를 보여야 같은 문장을 다시 안 낸다).
- **`held`(보류)는 `approved`와 같은 이유로 필요하다.** [확정]/[다시] 뿐이면 *"못 정하겠다"* 를 표시할
  데가 없어 그냥 넘어가고, 그러면 '초안 나옴'에 섞여 **안 읽은 것과 구분이 안 된다.**
  대기열은 `held`를 **건너뛴다** — 다시 그려도 교사가 안 정한 건 그대로고, 미뤄 둔 그 문장만 덮어써진다.
  재료가 아니므로 `material_at`을 건드리지 않고, 확정·[다시]·재료 변경이면 **자동 해제**한다.
- **`extra`(기타 요구사항)** — `competency`(무엇에)·`level`(얼마나)이 못 덮는 **분량·톤 축**이다.
  실측 근거: 교사가 "이 정도로 써주라"고 적었는데 683B 풀분량이 나왔고, `level='하'`로도 안 잡힌다
  (`하`는 도달 문장 한 절만 없앨 뿐 장면 묘사 분량은 남는다). 필드 도입 후 같은 학생 재렌더 → 172B.
  - 🚨 **교사가 여기 적은 사실은 써도 되지만 `ledger`에 `기타 요구사항:` 접두사를 강제**하고,
    화면은 `교사 요구사항(원문 근거 없음)`으로 따로 세운다. 금지해도 교사는 결국 `competency` 칸에
    적는다(실제로 그랬다) — **라벨 없이 새는 게 더 나쁘다.**
  - 우선순위 3층: **표면 규칙(바이트·금지어·종결) > `extra` > 계약서 문체 기본값.** 안전장치는 못 뚫는다.
  - 🚩 위임 학생에게선 `extra`가 원문을 통째로 대체할 수 있다(교사가 "쓸 게 없으니"라 했으면 옳다).
    다만 원문이 풍부한데 "짧게"만 적으면 좋은 재료가 버려질 수 있다 — 대량 작업 때 관찰할 것.
- 🔑 **`extra`·`why`·`competency`·`level`은 전부 재료다** — 하나라도 바뀌면 확정 해제 + `material_at` 갱신.
  새 재료 칸을 추가할 때 이 목록에 넣는 걸 빠뜨리면, **고쳐도 아무 일이 안 일어나는 조용한 고장**이 된다.

## `level` — 도달 진술의 허가 범위

| level | 허가 |
|---|---|
| **하** | 렌즈·역량 진술 **없이** 학생이 한 일 서술로 끝낸다. |
| **중** | 역량 진술을 쓰되 **`eval_lens`가 준 문구 범위 안에서.** 새 명제를 세우지 않는다. |
| **상** | 중 + **`eval_lens`의 '흔한 오답/얕은 수행의 모습'과의 대비**까지 진술 가능. |

🔑 **대비 대상은 공급받는 것이지 발명하는 게 아니다.**
스펙 `eval_lens`의 '흔한 오답/얕은 수행' 칸이 비어 있으면 **상은 중으로 붕괴한다.**
버그가 아니라 정의다 — 넘어설 대상을 교사가 주지 않았으면 넘어섰다고 쓸 근거가 없다.

🔑 **`level`은 부풀리기 허가가 아니다(헌법 2 > level).**
재료가 얇은데 `상`이면 지어내지 말고 재료만큼 쓰고 그 사실을 `notes`에 남긴다.

> **실증(2026-07-28, 한국사1 12명):** 레벨을 **무작위로** 찍어 렌더한 조작 점검.
> `하` 2/2에서 도달 진술이 사라지고 분량이 절반으로(평균 314B vs 상 627B·중 587B),
> `중` 0/4 · `상` 5/6으로 대비 진술이 갈렸다 — **노브는 재료와 무관하게 작동한다.**
> 동시에 **재료가 얇은 `상` 3건에서 대비항을 발명했다**(하이라이트 2개뿐인 학생에게
> "여러 사건이 흩어져 나열되기 쉬운 서술에서 벗어나"). 계약서에 "부풀리지 마라"를
> 적어둔 것만으로는 안 막혔다(4/12가 notes에 '재료 얇음'이라 쓰고도 대비절은 그대로 씀).
> → **대비 앵커를 스펙에서 공급하고, 없으면 상을 봉인**하는 지금 설계의 근거.

## 검수 루프 — 요청 → 초안 → 판정

**감시자가 대기열을 보고 굽고, 교사가 판정한다.** 대기열 판정은 결정론이어야 한다(사람이 기억하지 않는다).

| 상태 | 감시자 |
|---|---|
| 초안 요청됨(`done`), 초안 없음 | 그린다 |
| **[다시]** 눌림 | `material_at` 갱신 → 다시 그린다 |
| **[확정]** 눌림(`approved`) | **건너뛴다**(완료) |
| **[보류]** 눌림(`held`) | **건너뛴다**(판정 대기 — 다시 그리면 미뤄 둔 문장만 덮어써진다) |
| 확정 후 마킹 수정 | 확정 자동 해제 + `material_at` 갱신 → 다시 그린다 |

- 🚨 **대기열 규칙에 `approved` 제외를 반드시 넣는다.** 나머지 규칙이 *`done` && 마킹이 초안보다 최신*이라,
  승인도 파일 쓰기인 이상 이 줄이 없으면 **확정한 학생이 대기열에 재진입해 계속 다시 그려진다.**
- 🚨 **'마킹이 최신인가'의 기준은 파일 mtime 이 아니라 `material_at`이다.** mtime 은 재료와 무관한 쓰기에도
  갱신된다 — 확정·확정취소·반려 기록, `git checkout`, 파일 복사. 그걸 '마킹이 바뀌었다'로 읽으면
  **교사가 확정한 문장이 조용히 다시 그려져 덮어써진다.** `material_at`은 화면이 재료(하이라이트·`why`·
  `competency`·`level`)가 **실제로** 바뀐 순간과 [다시]에만 찍는다. 없는 레코드는 mtime 으로 폴백한다.
- **반려 딱지는 지울 필요가 없다** — 다시 그리면 초안이 더 최신이라 자연히 대기열에서 빠진다.
- **확정 자동 해제는 화면에서** — 하이라이트·`why`·`competency`·`level`·`extra` 중 하나라도 바뀌면
  `approved=false`(그리고 `held=false`).
  저장 경로가 한 곳이면 재료 지문 비교 몇 줄이다. 안 하면 "확정해놓고 마킹만 바뀐" **유령 상태**가 생긴다.
- **대기열 판정은 한 곳에서만.** 화면이 "이 초안이 지금 마킹의 결과인가"를 스스로 계산하면 감시자와 갈라진다
  (화면은 '초안 나옴'인데 감시자는 계속 다시 그리는 상태). 화면은 대기열 스크립트에 물어본다.
- **반려 사유는 다음 렌더 입력이다.** "이 이유로 물렸다"를 프롬프트에 실어 같은 실수를 막는다.
  사유가 비면 **그 회차의 스냅샷 본문을 붙여** "이건 물렸다, 다르게 써라"로 처리한다.
  스냅샷이 없는 옛 레코드는 디스크의 직전 초안 하나로 폴백한다.
- 🔁 **같은 학생 3회 반려 → "마킹을 손보라" 안내.** 문장이 아니라 재료(얇은 하이라이트·빈 `why`) 문제일 확률이 높다.
- 🚩 **같은 사유가 여러 학생에게 반복되면 그건 계약서·스펙 문제 신호다.** 개별 문장을 고치지 말고 스펙을 고친다.

## 사람 Tier-2 — 검수 자리

검증 구조는 **Tier-1 결정론 → 사람 Tier-2** 두 층이다(`DESIGN-DECISIONS.md` D4 + 2026-07-29 AI Tier-2 폐기).
**사람 Tier-2는 건너뛰지 않는다.** 다만 그 자리가 마킹 여부에 따라 다르다.

| 학생 | 사람 Tier-2 도구 | 사람이 보는 것 |
|---|---|---|
| **마킹함** | 마킹 화면의 **하이라이트 되짚기 패널 + [확정]/[다시]** | 세특 문장 ↔ **내가 칠한 자리**. 근거 줄에 손을 올리면 원문 하이라이트가 빛난다 |
| **위임**(마킹 0개) | `references/make_review_table.py` — 옆줄 대조표 | 세특 문장 ↔ 그 근거 스팬(원문 verbatim)을 나란히 |

- 마킹한 학생에게 옆줄 대조표를 또 만들 필요는 없다 — 근거의 출처가 **교사 자신의 마킹**이라 되짚기가 곧 대조다.
- 판정은 **[확정]/[다시]/[보류] 세 버튼**이다. 이관되는 건 `approved` 뿐이고, **[보류]는 "읽었는데 못 정함"을
  worklist 에 남기는 마커**다 — 없으면 그냥 넘어가서 '초안 나옴'(안 읽음)과 섞인다.
- 🚩 **위임 학생은 ⚠️(스팬 없는 문장)가 나올 자리가 근본적으로 넓다** — AI가 의미까지 골랐기 때문이다.
  대조표에서 눈에 띄게 표시하고, 반복해서 걸리면 다시 쓰지 말고 **그 학생을 마킹한다.**
- 🔑 **재료 날조는 AI 검수로 못 잡는다** — 문장이 그럴듯해서다. 지어냈는지 알려면
  "교사가 그 대비를 준 적 있나"를 알아야 하는데 그건 교사 머릿속에만 있다.
  그래서 **재료 단계 차단**(마킹 + 대비 앵커=스펙 공급, 없으면 `상` 봉인)이 사후 검수보다 확실하다.
  이게 2026-07-29에 AI Tier-2를 하네스에서 뺀 두 근거 중 하나다(다른 하나=실측 과잉, 137명 → 1건).

## 검증 (verify.py 변경 없음)

마킹 전용 검증기를 새로 만들지 않는다. 기존 Tier-1이 그대로 닫는다:

- `python3 verify.py <drafts> --levels <교사레벨맵>` → 교사가 준 `level`과 초안에서 추정한 톤을
  대조해 **인플레/디플레**를 낸다. 이게 곧 "레벨 지시를 따랐는가"의 검산이다(위임 학생은 `level` 미지정이면 대조 대상이 아니다).
- 표면축(바이트·금지어·명사형 종결·특수문자)은 마킹 여부와 무관하게 동일.
- **도달 진술 유무는 의미축이라 하드 판정하지 않는다(D3).** 특정 과제의 관용구
  (예: "이를 통해 …")를 정규식으로 하드게이트하고 싶으면 **프로젝트 폴더의 추가 검사로** 둔다.
  코어에 넣으면 그 과제 전용 하네스가 된다.
